# ポケカ 先着枠 空き通知ツール

[players.pokemon-card.com](https://players.pokemon-card.com/event/search) のイベント検索を定期的にチェックして、
**先着申込の空きが出た瞬間**に Mac の通知・音・読み上げ・ブラウザ自動オープンで知らせます。

## 使い方

```bash
cd "/Users/ayaka/Desktop/Cloude code/空き情報" && ./run.sh
```

止めるときは `Ctrl-C`。

| コマンド | 内容 |
| --- | --- |
| `./run.sh` | 常時監視（推奨。スリープ防止つき） |
| `python3 watch.py --status` | いま何がヒットしているか表示するだけ |
| `python3 watch.py --once` | 1回だけチェックして終了 |
| `python3 watch.py --test-notify` | 通知のテスト（Mac の音・読み上げ込み） |
| `python3 watch.py --test-push` | スマホ通知だけテスト（Mac は静か） |
| `python3 watch.py --reset` | 記録済みの状態をリセット |

初回起動時は「今の状態」を基準として記録するだけで通知は出ません。2回目以降、**状態が変化したときだけ**鳴ります。

## 監視条件を変える

`config.json` の `watches[].url` に、**ブラウザで検索した結果ページの URL をそのまま貼る**だけです。
条件を増やしたいときは配列に足し、いらない条件は `"enabled": false` にします。

```json
"watches": [
  { "name": "関東 エルレイド 8/2", "url": "https://players.pokemon-card.com/event/search?...",
    "prefectures": ["関東"], "enabled": true }
]
```

### 地域の絞り込み

**URL に都道府県は入りません**（サイトの絞り込みは URL に反映されない仕様）。
`prefectures` に書いてください。エリア名・県名・ID のどれでもOKで、混ぜても使えます。

| 書き方 | 例 |
| --- | --- |
| エリア名 | `["関東"]` `["関西"]` `["首都圏"]` |
| 県名 | `["東京", "神奈川", "埼玉"]` |
| ID | `[13, 14]` |

使えるエリア名: `北海道・東北` `東北` `北信越` `関東` `関東圏` `首都圏`（埼玉/千葉/東京/神奈川）
`中部` `関西` `四国・中国` `九州`

`prefectures` を書かなければ全国が対象です。

## 通知が出る条件

`config.json` の `rules` で切り替えられます。

| ルール | 内容 |
| --- | --- |
| `alert_on_full_cleared` | 満席だったイベントの**満席が解消**された（＝キャンセルで空きが出た）。**これが本命** |
| `alert_on_new_event` | 条件に合うイベントが**新しく掲載**された |
| `alert_on_status_open` | ステータスが「満席」→「先着受付中」に変わった／受付が再開された |
| `first_come_only` | `true` なら先着枠だけを対象にする（抽選は無視） |
| `alert_on_first_run` | `true` にすると、起動直後に空きがあった場合も通知する |

## 通知の設定（`config.json` の `notify`）

| キー | 内容 |
| --- | --- |
| `macos_notification` | 通知センターにバナーを出す |
| `sound` / `sound_repeat` | 鳴らす音（`/System/Library/Sounds/` の名前）と繰り返し回数 |
| `speak` / `speak_text` / `speak_voice` | 日本語で読み上げる（`Kyoko` は標準搭載の日本語音声） |
| `auto_open` | 空きが出たイベントの申込ページを自動でブラウザに開く |
| `ntfy_topic` | スマホへのプッシュに使うトピック名（設定済み） |
| `discord_webhook` | Discord に飛ばしたいとき。Webhook URL を入れる |

## スマホで受け取る（設定済み・無料）

**ntfy** を使います。アカウント登録も課金も不要です。

1. スマホに **ntfy** アプリを入れる（[App Store](https://apps.apple.com/app/ntfy/id1625396347) / [Google Play](https://play.google.com/store/apps/details?id=io.heckel.ntfy)）
2. アプリで「＋」→ **`.env` に書いてあるトピック名**（`NTFY_TOPIC` の値）を入力して購読する

   トピック名は合言葉なので、このリポジトリには載せていません。手元の `.env` を見てください。

   ```bash
   cat "/Users/ayaka/Desktop/Cloude code/空き情報/.env"
   ```

3. 送信テスト（Mac側は音を出しません）

   ```bash
   cd "/Users/ayaka/Desktop/Cloude code/空き情報" && python3 watch.py --test-push
   ```

購読するとテスト通知が届きます（送信済みのものも12時間ほどはさかのぼって表示されます）。

通知をタップすると、そのイベントの申込ページが直接開きます。優先度は urgent なので、
消音中でも鳴りやすい設定です（iOS は「設定 > 通知 > ntfy」で時間指定サマリーをオフにしておくと確実）。

> **トピック名は合言葉です。** 知っている人は誰でも購読できてしまうので、人に教えないでください。
> 変えたいときは `.env` の `NTFY_TOPIC` と GitHub の Secret を書き換えて、アプリ側も購読し直します。

## Mac を閉じていても監視する（GitHub Actions）

`.github/workflows/watch.yml` が **5分おきに自動でチェック**します。Mac の電源は不要、費用もかかりません。

### 初回セットアップ

1. GitHub で**公開(Public)**リポジトリを作る
   （Public にしないと Actions の無料枠を使い切ります。トピック名は Secret に隠すので公開して問題ありません）

2. このフォルダを push する

3. リポジトリの **Settings > Secrets and variables > Actions > New repository secret** で登録

   | Name | Secret |
   | --- | --- |
   | `NTFY_TOPIC` | `.env` に書いてあるトピック名 |

4. **Actions** タブ →「ポケカ先着枠の空き監視」→ **Run workflow** で手動実行して、緑になるか確認

### 動きかた

- 5分おきに1回チェックし、空きが出たら ntfy でスマホに通知
- 結果は `state.json` に保存され、**変化があったときだけ**自動コミットされます
- **取得に失敗したら実行が「赤」になります**（ブロックを「空きゼロ」と誤認しないための仕組み）。
  GitHub から失敗メールが届くので気づけます

### 注意

- GitHub の混雑時、スケジュール実行は **5〜15分ほど遅れる**ことがあります
- Mac 版（60秒間隔）と併用できます。両方とも同じトピックに通知するので、
  在宅時は `./run.sh` を回しておくとより早く気づけます
- 万一 GitHub のIPが Cloudflare に弾かれる場合、実行が赤くなり続けます。そのときは Mac 版に戻すか、別の実行場所を検討してください

## Mac 版の落とし穴

### ふたを閉じると止まります

`caffeinate` は「放置によるスリープ」は防ぎますが、**ふたを閉じたときのスリープは防げません**。
スリープ中は監視されず、復帰直後は Wi-Fi が繋がるまで `DNSError`（名前解決失敗）が出ます。

ログがこうなっていたら、スリープしていた証拠です。

```
[07:06:50] ... 0件ヒット
[08:41:01] ... エラー: DNSError    ← 1時間半の空白 = スリープしていた
```

ネットワーク断のときは通常間隔を待たず **15秒おきに再試行**し、復帰時に
「約○分ぶん監視できていませんでした」とログに残します。

外出中も動かすなら、**電源につないでふたを開けたまま**にしてください。

### 二重起動はできません

`./run.sh` を2回叩くとアクセス頻度が倍になり、ブロックされやすくなります。
すでに動いている場合は起動を中止し、動作中のPIDを表示します。

## 仕組みと注意点

- 画面の裏で動いている JSON API `https://players.pokemon-card.com/event_search?（検索と同じクエリ）` を叩いています。
- 都道府県は `prefecture[]=13&prefecture[]=14` の形式。`prefecture_id=13` は**黙って無視される**ので注意。
- 該当0件のとき、この API は **HTTP 404 +「イベント情報が存在しません。」** を返します（エラーではない）。
- 検索条件の `accepting=true`（受付中のみ）が空き検知の要です。満席になったイベントは結果から消え、
  キャンセルで空きが出ると再び現れます。だから「結果に出てきた＝申し込める」になります。
- このサイトは **Cloudflare** で保護されていて、普通の `curl` / `requests` は 403 になります。
  そのため TLS フィンガープリントを偽装できる `curl_cffi` を使っています（インストール済み）。
  もし未導入の環境なら: `python3 -m pip install --user curl_cffi`
- **短時間に連続アクセスするとブロックされます**（実測: 3秒間隔でも5回連続で弾かれた）。
  デフォルトは 60秒 ± 15秒 のゆらぎ付き間隔で、弾かれたら自動で待機時間を倍にして再開します。
  `poll_interval_sec` を 30 秒より短くするのはおすすめしません。サイトに負荷をかけると恒久的にブロックされる可能性があります。
- 監視中は Mac をスリープさせないでください（`run.sh` は `caffeinate` でスリープを抑止します）。ふたを閉じると止まります。
